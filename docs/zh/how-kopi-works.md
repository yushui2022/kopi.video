# 从一条参考视频到一条新广告：Kopi.video 的视频复刻原理

> 这篇文章分三部分：
>
> 1. **先讲 AI 视频生成到底在生成什么**——为什么“看起来像视频”和“能用来投放”是两件事。
> 2. **再讲 Kopi.video 做了什么**——它怎么把一条参考视频拆成结构，再用你的产品和 AI 演员重做一遍。
> 3. **最后拆开项目的技术原理**——Agent、视频理解、方案卡、生成流水线、渲染、版本和成本控制。
>
> 适合想了解 AI 视频产品的人，也适合想知道 Kopi 到底怎么工作的人。

## 一、AI 视频生成，不是在“画一张会动的图”

人眼看视频，看到的是连续的动作。模型看到的是一串有时间关系的画面：每一帧都要和前一帧对得上，人物不能突然换脸，产品不能变形，口型不能和声音脱节。

所以视频生成至少同时解决三件事：

| 层面 | 要解决的问题 | 失败时用户看到什么 |
|---|---|---|
| **外观** | 这一帧长什么样：人物、产品、光线、材质 | 产品变形、logo 糊掉、手变成了六根手指 |
| **运动** | 东西怎么动：动作、镜头、物理 | 人物走路像滑行、物体穿模、镜头乱晃 |
| **时间** | 前后怎么连：身份、颜色、场景、节奏 | 看着看着换了一张脸、衣服颜色跳变、画面闪烁 |

图片生成只要“这一帧好看”就够了；视频生成还要“下一帧也成立”。这就是为什么很多模型单帧很惊艳，一动起来就露馅。

### 1. 从噪声到画面：扩散模型的一句话版

目前常见的视频生成模型，多数可以归到**扩散模型 / 扩散 Transformer** 这一类；也有自回归等其他路线。不用纠结名词，先理解一个直觉：

> 模型先学会“把一张图一步步加噪，直到变成纯噪声”；生成时反过来，从纯噪声开始，一步步去噪，最后得到一张图。

视频版本就是把这个过程扩展到时间维度：不只是每一帧去噪，还要让相邻帧互相“看一眼”，保持人物、物体和背景的连贯。

实际模型通常不会在原始像素上直接算，而是在一个压缩过的**潜空间（latent space）**里算：

```text
原始视频
  → 编码器压缩成 latent（保留结构和运动，丢掉冗余像素）
  → 在 latent 上反复去噪
  → 解码器还原成像素
```

可以把它想成：先画一张很粗的草图，在草图上反复修改，最后再放大成高清画面。这样计算量小得多，模型才能生成几秒钟的高分辨率视频。

### 2. 条件控制：文字、图片、参考视频，各管什么

模型不会凭空知道你想要什么，它需要“条件”：

| 条件 | 主要控制什么 | 典型用法 |
|---|---|---|
| **文字 prompt** | 语义：谁、在哪、做什么、什么风格 | “一个女生在厨房拿着护肤品，晨光，近景” |
| **首帧 / 参考图** | 外观：人物长相、产品样子、构图 | 用产品图或演员图锁定第一帧 |
| **参考视频** | 运动 / 结构：动作、镜头、节奏 | 让演员照着一条视频的动作演 |
| **姿态 / 深度 / 分割** | 精确控制：骨架、空间关系 | 更专业的视频转视频工作流 |
| **音频** | 口型、节奏、情绪 | 让角色按台词说话 |

对 Kopi 来说，**参考视频不是“风格参考”，而是“结构参考”**。我们不是让模型把原视频加个滤镜，而是先读懂它的 hook、节奏、镜头顺序，再用新的产品、演员和脚本重新生成。

### 3. 视频理解：把“感觉”变成结构

一条爆款视频，人看完了会说“说不上来为什么，就是很抓人”。但生成模型需要的不是这种感觉，而是一份可执行的结构：

- 前 0~2 秒，钩子是什么？
- 第 2~7 秒，产品怎么出现？
- 第 7~12 秒，证明了什么？
- 第 12~15 秒，CTA 怎么说？
- 镜头是近景、手持、还是口播？
- 音乐和台词的节奏是快还是慢？

这一步通常由**多模态大模型**完成：它抽帧、看画面、听音频，然后输出一份结构化 JSON。可以把它理解成“导演拆片”：把一条成片拆成场次、节拍、台词和意图。

这份结构，是后面所有生成工作的“图纸”。没有它，所谓复刻就退化成“照着感觉再生成一条”，稳定性完全靠运气。

### 4. 真正的难点，不在“生成”，在“可控”

视频生成模型这几年进步很快，但把它用到广告生产里，难点是另一组：

| 难点 | 具体表现 | 为什么难 |
|---|---|---|
| **时间一致性** | 人物换脸、衣服变色、背景跳动 | 每一帧都要和前后帧协商，误差会累积 |
| **产品保真** | logo 变形、包装文字糊、材质不对 | 产品是客户最不能错的部分，模型却最容易自由发挥 |
| **手和物体** | 手指数量不对、拿产品穿模 | 手部结构复杂，遮挡多 |
| **文字渲染** | 包装上的字、字幕、价格标签 | 像素级文字对生成模型仍然难 |
| **物理** | 液体流动、布料、重力 | 模型学的是统计规律，不是物理引擎 |
| **音频与口型** | 口型和台词对不上、声音不像 | 视频和音频是两个系统，要对齐 |
| **可控性** | 想只换产品，结果脸也变了 | 模型很难理解“什么该变、什么不该变” |
| **成本与延迟** | 一条 15 秒视频要几分钟到几十分钟 | 先生成再发现问题，钱已经花了 |

所以，**“能生成一条看起来不错的视频”只是起点；“能稳定生成一条客户敢拿去投放的视频”才是产品**。

### 5. 为什么“复刻”比“生成”更难

普通文生视频的目标是：给我一条合理、好看、符合 prompt 的视频。

复刻的目标是：**保留参考视频的结构，换掉产品、演员、台词和画面，同时不抄袭原片。**

这中间多了四件事：

1. **理解**：先看懂参考视频为什么有效。
2. **规划**：把结构变成可执行的场次、节拍、台词和 CTA。
3. **控制**：生成时只改该改的，保留该保留的。
4. **组装**：把多个片段、配音、字幕、音乐拼成一条完整广告。

这也是 Kopi 把“复刻”当成一等公民的原因：它不是给生成模型加一个按钮，而是围绕“理解 → 规划 → 生成 → 组装”做了一整条流水线。

## 二、Kopi.video 是什么

### 1. 一句话

**Kopi.video 是一个面向电商和增长团队的 AI UGC 广告生成器：粘贴一条你有权使用的参考视频，Kopi 拆出它的 hook、节奏和镜头结构，再用你的产品、脚本和 AI 演员重做成一条 9:16 广告。**

它的口号是：

> **Keep the structure. Make it yours.**
>
> 保留结构，换成你的。

### 2. 它解决的不是“生成”，是“复刻”

大多数 AI 视频工具的工作方式是：

```text
写 prompt → 生成 → 不满意 → 改 prompt → 再生成
```

Kopi 的工作方式是：

```text
给参考 / 产品 → 拆结构 → 出方案 → 你批准 → 生成 → 只重做有问题的那一场
```

差别在于：**前者把不确定性留给你，后者把不确定性收进方案里。**

### 3. 一次完整的复刻

假设你卖一款护肤品，看到一条爆款视频：

> “我用了 7 天，第 3 天开始有变化，第 7 天同事问我是不是换护肤品了。”

Kopi 会把它拆成类似这样的结构：

| 时间 | 参考视频在做什么 | Kopi 的方案 |
|---|---|---|
| 0~2s | 近景，素颜，第一句钩子 | 你的 AI 演员，同一句式的钩子，换产品 |
| 2~7s | 展示产品，讲使用方式 | 你的产品特写，新的使用场景 |
| 7~12s | 展示变化 / 证据 | 你的产品卖点，新的证明方式 |
| 12~15s | CTA | 你的 CTA，按平台习惯改写 |

然后它会把方案卡给你看：用哪个演员、哪个模板、几段、每段多长、用什么模型、大约多少 credits。

你点 **Approve**，它才开始生成。

生成完，如果第 2 场的产品特写不对，你只需要重做第 2 场；第 1 场和第 3 场不动。

这就是“复刻”和“重新生成”的区别：**复刻是有图纸的，重新生成是碰运气。**

### 4. 和普通 AI 视频工具的区别

| | 普通 AI 视频工具 | Kopi.video |
|---|---|---|
| **起点** | 一句 prompt | 一条你信得过的参考视频 |
| **复用什么** | 风格、感觉 | hook、节奏、镜头结构 |
| **花钱时机** | 生成前就扣 | 方案批准后才扣 |
| **改错方式** | 整条重生成 | 只重做一场 |
| **演员** | 随机、容易换脸 | 17 个 AI 演员，尽量保持同一张脸 |
| **输出** | 画幅、时长不稳定 | 9:16，10s/15s 分段，原生配音和字幕 |
| **透明度** | 不知道钱花在哪 | 方案里写清演员、模型、时长、credits |

### 5. 适合谁，不适合谁

**适合：**

- Shopify / DTC 卖家，每周要上新素材，但请不起真人 UGC。
- App / SaaS 增长团队，需要大量 hook 做 A/B。
- 小型广告代理，要帮多个客户快速出片。
- 想蹭热门格式、但不想从零写脚本的创作者。

**不适合：**

- 需要电影级质感、复杂调度、多人打斗的片子。
- 需要真实人物证言、医疗/法律等高风险宣称的广告。
- 没有产品图、没有明确卖点、也不愿意提供参考的“空白需求”。
- 想直接复制别人视频画面、音乐、台词的需求——Kopi 只复刻结构，不做盗用。

## 三、Kopi 的项目原理

下面这部分，拆开看 Kopi 是怎么把上面的产品体验做出来的。

### 1. 总体架构

```text
浏览器（TanStack Start SSR + React）
  │
  ├─ 页面 / SEO / 博客
  │
  └─ /api/* ──► Hono on Cloudflare Workers
                 ├─ 登录、计费、素材、管理
                 └─ /ws ──► StudioSession（Durable Object）
                              ├─ 会话消息 / 状态（SQLite）
                              ├─ Agent runtime（工具调用）
                              └─ 方案卡 / 进度卡 / 成片卡
  │
  ├─ Cloudflare Workflow（长任务）
  │    ├─ 扣费
  │    ├─ 首帧
  │    ├─ 视频生成 + 轮询
  │    ├─ 配音 / 字幕
  │    ├─ FFmpeg 渲染
  │    └─ 回调 / 失败退款
  │
  ├─ D1：用户、积分、生成任务、会话索引
  ├─ R2：上传、参考视频、首帧、分段、成片
  └─ Container：Node + FFmpeg 合成
```

这个架构的核心不是“用了什么云”，而是三个选择：

1. **会话有状态**：一条广告是一个持续的项目，不是一次 HTTP 请求。
2. **生成是长任务**：几分钟到几十分钟，不能用普通请求扛。
3. **钱和生成必须分开**：先方案、后扣费，失败要能退。

### 2. 对话式 Agent：一个会话就是一个项目

用户进入 Studio，看到的不是一堆表单，而是一个对话框。这个会话背后是一个 **Durable Object**：

- 每个会话有独立的 SQLite，存消息、方案、状态。
- WebSocket 保持连接；刷新页面可以恢复。
- 会话可以同时处理“聊天”和“生成进度”，不会因为一个长任务把整个页面卡死。

Agent 的职责不是直接“生成视频”，而是**理解意图、选工具、补参数、把方案讲清楚**。它有几类工具：

| 工具 | 作用 |
|---|---|
| `analyze_video` | 拆解参考视频：hook、节奏、场次、音频、CTA |
| `search_templates` | 从模板库里选合适的广告结构 |
| `pick_actor` | 从演员库选人，或确认用户自带的演员 |
| `propose_plan` | 生成方案卡：场次、时长、模型、credits |
| `propose_motion` | 换人：把演员换进现有视频，保留动作/镜头/背景 |
| `propose_first_last` | 长视频复刻：按镜头锁首尾帧，逐段生成 |
| 编辑工具 | 裁剪、变速、重排、删除、替换、重做单场 |

关键点：**Agent 只做规划和调度，不直接碰付费生成。** 真正的付费动作在用户批准方案之后，由运行时强制执行。

### 3. 参考视频怎么被“读懂”

一条 TikTok / 抖音链接进来，后面发生的事大致是：

```text
链接
  → 解析出视频地址
  → 下载到 R2
  → 多模态模型读取实际视频字节
  → 输出结构化拆解
  → 校验 / 修复 JSON
  → 存成拆解卡
```

为什么要下载实际字节，而不是把 URL 丢给模型？

- 很多平台的视频 URL 有时效、防盗链、需要登录。
- 模型直接读 URL 的成功率不稳定。
- 先把视频落到自己的存储，后续拆解、换人、复刻都能复用同一份素材。

拆解的输出不是一段散文，而是一份结构：

```json
{
  "hook": "前 2 秒说了什么、画面是什么",
  "structure": ["钩子", "产品出现", "证明", "CTA"],
  "pacing": "快/慢、镜头切换频率",
  "audio": "口播/音乐/环境音",
  "cta": "最后一句是什么",
  "whyItWorks": "为什么这条片子有效",
  "replicable": "哪些部分可以复刻",
  "people": "画面里有几个可替换的人物/角色"
}
```

这份结构会直接进入方案卡，成为后续生成的“图纸”。

### 4. 方案卡与成本门禁

Kopi 最核心的产品原则是：**确认才花钱。**

方案卡里会写清：

- 用哪个模板（product in hand、unboxing、POV hook……）
- 用哪个 AI 演员
- 分几场、每场多长
- 用什么模型
- 预计多少 credits

用户点 **Approve** 之后，方案状态变成 approved，才允许调用付费工具。运行时有一道成本门禁：

```text
propose_plan（免费）
  → 用户批准
  → 生成任务创建
  → 扣费（幂等键）
  → 调模型
  → 失败自动退款
```

积分是**只追加的流水**，每一笔都有幂等键，避免重试时重复扣费。生成失败会退款，用户不会为一条废片买单。

这不是“体验优化”，是这类产品能不能被信任的基础。

### 5. 生成流水线

一条广告的生成，不是“调一次模型”就结束了。实际流水线大致是：

```text
1. 扣费（幂等）
2. 并发生成首帧（最多 3 段）
3. 并发提交视频任务（最多 3 段）
4. 轮询任务状态，直到完成或超时
5. 需要时生成配音
6. 生成字幕时间轴
7. 用 FFmpeg 拼接、混音、烧字幕
8. 写入成片、回调会话、展示进度
9. 失败：退款、记录原因、允许重试
```

几个工程上的选择：

- **分段生成**：广告按 10s / 15s 分段，而不是一次生成 30 秒。这样失败可以只重做一段，成本可控。
- **并发**：首帧和视频提交可以并发，缩短总时长。
- **幂等**：每段有 task_id，重试时先查再提交，避免重复扣费。
- **超时与退款**：供应商可能排队、失败、超时；系统要能兜底，而不是让用户等一个永远不会来的结果。
- **模型适配层**：模板不写死模型，只声明需要什么能力（参考视频、首帧、换人、长视频），由适配层选模型。

### 6. 渲染：为什么还需要 FFmpeg

模型生成的是“段”，不是“成片”。一条可投放的广告还需要：

- 把多段拼在一起
- 统一画幅、帧率、编码
- 混音（人声、音乐、环境音）
- 烧字幕
- 写 AI 标识
- 输出一个 MP4

这些工作由 Cloudflare Container 里的 Node + FFmpeg 完成。模型负责“生成画面”，渲染层负责“把画面变成可交付的文件”。

### 7. 编辑与版本：只重做该重做的那一场

生成完之后，用户经常只需要改一个地方：

- 第 2 场的产品特写不对
- 第 3 场的台词太长
- 结尾的 CTA 想换一个说法
- 想把某一段删掉/调快/换顺序

Kopi 把编辑分成两类：

| 类型 | 例子 | 是否扣费 |
|---|---|---|
| **确定性编辑** | 裁剪、变速、重排、删除、替换 overlay、重新合成 | 免费 |
| **生成式编辑** | 重做某一场、增加一场、改台词/画面 | 需要方案 + 扣费 |

每次生成都会保留版本，用户可以回退。这样“改一版”不会把之前的成果覆盖掉。

### 8. 数据与状态

| 数据 | 存在哪 | 为什么 |
|---|---|---|
| 会话消息、当前方案、时间线 | Durable Object SQLite | 每个会话独立、低延迟、可恢复 |
| 用户、积分、生成任务、会话索引 | D1 | 跨会话查询、对账、后台 |
| 上传、参考视频、首帧、分段、成片 | R2 | 媒体文件大，对象存储更合适 |
| 积分流水 | D1（append-only） | 可审计、幂等、防重复扣费 |

这套划分的原则是：**会话状态靠近会话，业务数据靠近数据库，媒体靠近对象存储。**

### 9. 可靠性与合规

- **登录**：Google OAuth + Magic Link；CSRF、Turnstile、限流。
- **扣费**：只追加流水、幂等键、失败退款。
- **AI 标识**：成片写入 AI 元数据，并提供 `/verify` 页面读取文件校验。
- **版权/肖像**：参考视频必须有权使用；真实人物 likeness 需要授权；不复制原片画面/音乐/台词。
- **SEO/GEO**：SSR、canonical、sitemap、结构化数据、`llms.txt`，让搜索引擎和 AI 能读懂产品。

### 10. 为什么是 Cloudflare

Kopi 是“有状态 + 长任务 + 媒体重”的产品，Cloudflare 的几块能力刚好对上：

| 需求 | Cloudflare 能力 |
|---|---|
| 全球低延迟 | Workers |
| 每个会话独立状态 | Durable Objects |
| 长任务编排 | Workflows |
| 关系数据 | D1 |
| 媒体存储 | R2 |
| 重计算渲染 | Containers |

代价也要说清楚：

- Workers 有 CPU/内存限制，不能把它当普通服务器用。
- Container 有冷启动和实例上限，高并发要排队/限流。
- 分布式系统更难调试，日志和可观测性要补。
- 供应商锁定是真实存在的，迁移成本要提前算。

选它不是因为“时髦”，是因为这个产品天然适合“边缘 + 有状态 + 长任务”的组合。

## 四、边界与未来

Kopi 不是一个“一键出大片”的魔法按钮。它擅长的是：

- 有明确产品图的电商广告
- 有参考结构的 UGC 风格视频
- 需要快速测试多个 hook / 演员 / 版本的增长团队

它不擅长的是：

- 电影级复杂调度
- 高精度产品文字/包装还原
- 没有授权素材的“搬运式复刻”
- 需要真人证言/高风险宣称的广告

接下来我们会继续做：

- 批量变体：一个方案出多个 hook / 演员版本
- API / MCP / CLI：让代理和增长团队接入自己的工作流
- 更多模型、更高分辨率、更好的长视频处理
- 更多模板和更细的演员控制
- 更好的中文体验，服务中国出海卖家

## 结语：复刻不是复制

一条视频有效，通常不是因为某个像素，而是因为它在一个特定的时间点，用特定的节奏，说了一句特定的话。

**复刻不是把原片换个滤镜，而是先理解它为什么有效，再用你的产品、你的演员、你的话，重新生产一遍。**

Kopi 做的，就是把这件事拆成可执行的步骤：

```text
理解结构 → 形成方案 → 你批准 → 生成 → 只改该改的 → 交付
```

这就是我们理解的“视频复刻平台”。
